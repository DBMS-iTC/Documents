= Technical Decision TD_DBMS_B_002: Additional Configurable Session Limiting Mechanisms
:issued-date: 2024-06-20
:published-date: 2024-06-24
:affected-pp: DBMS Collaborative Protection Profile (cPP) v1.3

== Issue

The current version of the DBMS cPP provides an option for session limiting mechanisms but does not mandate the inclusion of FTA_MCS_EXT.1. Stakeholders have requested clarification on whether FTA_MCS_EXT.1 should be mandatory and how it should be implemented and tested.

== Resolution

FTA_MCS_EXT.1 (Configurable Session Limiting Mechanisms) is now a mandatory requirement for the DBMS cPP.
This includes the option to use FTA_MCS.1, as permitted by the current cPP.
The following requirements and evaluation activities apply:

=== New Mandatory SFR

*FTA_MCS_EXT.1 Configurable Session Limiting Mechanisms*

- *FTA_MCS_EXT.1.1*: The TSF shall restrict the maximum number of concurrent sessions based on [selection: _User session locking as defined by FTA_MCS.1_, [assignment: _mechanism(s) for session limitation enforced by the TSF_]].
- *FTA_MCS_EXT.1.2*: The TSF shall provide the capability for an authorized administrator to configure the selected enforcement mechanisms.

=== Change to Selection-Based SFR

*FTA_MCS.1 Concurrent Session Control*

- *FTA_MCS.1.1*: The TSF shall restrict the maximum number of concurrent sessions that belong to the same user.
- *FTA_MCS.1.2*: The TSF shall enforce, by default, a limit of [assignment: default number] sessions per user.

== Evaluation Activities

The following Evaluation Activities shall apply to FTA_MCS_EXT.1 

=== TSS (Security Target)
The evaluator shall examine the TSS and verify that it states the default number of concurrent sessions for the evaluated configuration. If the default number of concurrent sessions can be changed then the evaluator shall verify that the TSS states the default can be changed.

=== Guidance Documentation
The evaluator shall examine the guidance documentation and verify that it states how to set the default number of sessions and, if applicable, how the default can be changed.

=== Tests
The evaluator shall establish the maximum number of concurrent sessions and verify that this number of concurrent sessions is allowed. The evaluator shall attempt to establish a number of sessions greater than the maximum specified and verify that additional concurrent sessions cannot be established.

If the default number of concurrent sessions can be changed then the evaluator shall change the default value and repeat the test.

== Rationale

The ITC determined that limiting concurrent sessions solely by user (as in FTA_MCS.1) did not cover all security or policy needs. By making FTA_MCS_EXT.1 mandatory, the cPP explicitly allows for additional or alternative session limiting mechanisms—beyond user-based restrictions—such as those based on roles, connection sources, or other relevant criteria. This improves flexibility and ensures that a broader range of session management controls can be evaluated and implemented, aligning the cPP with evolving security requirements and deployment scenarios.

== Impact

This Technical Decision is effective immediately and shall be cited in all relevant cPP evaluations and corresponding SD evaluation activities.
